## Why catering is a different product than a restaurant site

| Restaurant                    | Catering                                                                |
| ----------------------------- | ----------------------------------------------------------------------- |
| Individual dish + price       | Package built around event, guest count, service                        |
| Instant order/checkout        | Enquiry → human quote → negotiation                                     |
| Repeat, low-trust transaction | High-value, high-trust, infrequent purchase                             |
| Menu is the product           | Menu + experience + hygiene + photography + testimonials is the product |

Trust, food photography, event photography, and clear menu/package framing matter disproportionately because the buyer is committing a large sum, sight-unseen, for an irreversible date (a wedding, a launch event). Food-safety signals matter for the same reason — but the client has supplied **no** FSSAI licence, no hygiene certification and no kitchen or ingredient-sourcing detail, so none is published. That gap is logged in Sec. 11 rather than filled with generic assurance copy.

## Core business objective

> **Generate qualified catering enquiries and convert them into booked events.**

## Secondary goals

- Establish positioning distinct from the QSR brand
- Build trust via real event photography and customer testimonials (neither supplied yet — see Sec. 05)
- Showcase cuisines, food options and customisation without publishing unconfirmed pricing
- Make WhatsApp/phone contact effortless
- Improve local SEO (Bhubaneswar + event-type keywords)
- Support the sales team's quotation workflow, not replace it

## Core funnel

```
Discover → Understand services → Explore event type → Explore menu →
View gallery → Build trust (testimonials/hygiene) → Get a Quote →
Submit enquiry → WhatsApp/phone follow-up → Quotation → Booking → Event
```
